# Security review - M8b (client portal screens)

Reviewer: Security Agent. Method: static review (no Docker, no dynamic testing). M8a findings (docs/reviews/security-m8a.md) are not re-reported.
Tools: `dotnet list package --vulnerable` and gitleaks were not run here (CI runs both: `.github/workflows/ci.yml:36,50`). Risky-API greps run: `MarkupString`, `innerHTML`, raw `href="@..."` from data, `IgnoreQueryFilters`: no hits in the M8b scope.

## Verdict: PASS-WITH-CONDITIONS

No Critical or High findings. Two Medium findings (M8b-01, M8b-02) should be fixed before release; the rest are Low/Info.

## Checked and found sound
- One-time secrets: shown only in `SecretRevealDialog` (no escape/backdrop close, confirm checkbox); not logged anywhere in `Services/Api/*`, `Security/*` (only status/code logged); not put in storage or the URL; JS interop receives it only for the explicit Copy click.
- Route ids are typed `Guid` and the API derives the tenant from the credential, so a foreign profile/key/webhook id gets API 404 (UI adds no client id). Settings route comes from the fixed `SettingGroups` map. Per-page `[Authorize]` permissions match the API's `[HasPermission]` for keys, webhooks, logs, faces, notifications, usage. Create/edit user roles are limited to the two built-ins in the UI (API must still enforce; covered by M8a/API reviews).
- XSS: API-doc samples and webhook URL/last error/disabled reason/metadata/ExternalRef are rendered as Razor-encoded text; `CodeSample` uses `<pre><code>@Code`; no `MarkupString`. Samples contain placeholders only, no `-k`/`--insecure`, no real hosts or keys.
- Erase flow: typed phrase "ERASE" in both list and detail, `faces.erase` gated by `<Can>` and by the API; history shows "Erased" for removed profiles.
- ApiGateway multipart: content disposed with the request; 401 replay re-sends the same bytes and headers (idempotency key preserved).
