## M9b notes (scalability, multi-node, operations)
- **Shipped:**
  1. **Shared rate-limit and daily-quota counters.** `api.UsageCounters` (bucketed per UTC minute / day, atomic single-statement upsert, purged by every node) behind an in-memory fast path: a node reserves a block of permits (`limit / 20`, 1..50) and hands them out locally, so about one call in `block` touches SQL. The sum over nodes never exceeds the limit (tested: two limiter instances and two complete API hosts on one database). Falls back to per-node counting (warning, rate-limited) when SQL is unreachable or `Counters:Shared=false`. A call refused by the daily quota returns its minute permit.
  2. **Webhook dispatcher.** Per-endpoint fairness (`Webhooks:MaxPerEndpointPerCycle`, windowed claim `ROW_NUMBER() OVER (PARTITION BY EndpointId)` re-checked under `UPDLOCK, READPAST` so two nodes never claim a row), configurable `BatchSize`/`Parallelism`/`TimeoutSeconds`/`LeaseSeconds` (explicit lease shorter than the worst case refused at start-up), consecutive failed **events** (an event counts once, on its first failed attempt; success resets; test events never count; `Webhooks:DisableAfterFailedEvents`), per-principal throttle on `POST .../test` and `.../retry`.
  3. **Portal shared store.** `PortalCache:Provider` = `Memory` | `SqlServer` | `Redis` for the session store, the pending-MFA challenge and the export throttle (`deploy/sql/portal-cache.sql`, `EnsureTable`, validated identifiers, startup guard replaces the in-memory opt-in); documented in `deploy/CONFIG.md`.
  4. **Throttle and exports.** `[Throttle]` filter (shared counters, per user / API key) on both dashboards, both CSV exports and the webhook test/retry actions; CSV streaming now pulls header + first row before sending (a failure there is a normal 500 problem response), aborts the connection on a later failure (logged without row content) and starts with a UTF-8 BOM; the portal relay aborts too. **Ledger break alert once:** Critical 7001 + audit when first found, reminder every `ReminderDays` (default 7, 0 = never), Warning 7003 in between, open findings in `GET /admin/licensing/ledger-breaks` (new columns `AlertedAt`, `LastReminderAt`).
  5. **Load and recovery.** `tests/Load` (k6 script `faces.js`, .NET driver `NexaVerify.Load` with a smoke test in `Api.IntegrationTests`, README), `deploy/scripts/backup-restore-drill.sh` (verified here against a real SQL Server container, 36 tables, DBCC and ledger check), `docs/runbooks/backup-restore.md`, `Migrator verify-ledger`, and `BackupRestoreDrillTests` (backup, restore under another name, ledger verification clean with the right key, failing with the wrong key or an altered ledger).
  6. **Cheap lows:** portal `ApiCallOptions.Headers` allow-list (only `Idempotency-Key`; M8 open item), CSV relay forwards the person's address (N-5), download throttle shared when a shared cache is configured (N-4), `gitleaks` was already in CI (M5 item closed).
